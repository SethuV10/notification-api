The RLVMP model integrates three intelligent modules that collaborate in order to solve the fluid VM placement problem. The process of work is in a continuous loop of monitoring, analysis, decision-making, and execution. It begins with the Monitoring Module of CloudSim, which tracks the use of resources (CPU, RAM, Network, I/O) of all currently running Physical Machines. This real time information is forwarded to the Q-learning Agent. Meanwhile, any VM that is waiting to be placed or has been targeted to migrate is sent to the RF-SOM Classification Module that pre-processes the characteristics of the VM and labels it with a sensitivity. The Q-learning agent, having known about the state of the system and guided by the sensitivity context of the classifier via the VM, reviews its policy (the Q-table) in order to select an action. This may be a high level command, like consolidate VMs on an underused host or migrate VMs on an overused host. After selecting a migration action, the respective VMs are forwarded to the Allocator that is based on the Firefly Algorithm. This allocator works out in potential destination PMs, with an assessment of placement quality determined based on load balance and VM sensitivity with the help of a fitness function. The outcome is an optimal or almost optimum mapping of VMs to PMs. The new arrangement is then implemented in CloudSim. This action is then measured by the Reward Calculation Module which considers the outcome of the action (energy consumption and SLA infraction) and feeds the scalar reward to the Q-learning agent. This feed-back mechanism enables the agent to keep on making its policy better so that it can better administer the data center with time.
5.2. Phase 1 VM Sensitivity Classification.
5.2.1. Description and Preprocessing of data sets.
We use the Microsoft Azure 2019 Public Dataset, a real-life trace of a cloud environment as the foundation of our classification model. The primary files used are vmtable.csv which contains static data on over 2.6 million VMs (subscription ID, deployment ID, core count, memory) and the file vm-cpu-readings-file*-of-195 series that provides time-series CPU utilization data, sampled at a rate of 5 minutes. We used comprehensive data preprocessing, which included:
(1) Data Cleaning: Dealing with missing or other anomalous data by interpolating or dropping them.
(2) Feature Engineering: Deriving a composite feature set to each VM comprising of Average_CPU, Max_CPU, CPU_Variance, VM_Lifetime, Core_Count, and Memory_GB.
(3) Data Normalization: Transforming all numerical variables to the [0,1] scale to make sure none of the variables dominate the learning process because of its magnitude.
5.2.2. Feature Engineering and Selection.
The features chosen were so because of their direct sensitivity to the disruption and their sensitivity to the performance characteristics of a VM.
Parameters: Average and Max CPU: This represents the amount of computation the workload demands.
• CPU_Variance: A large variance implies that the workload is bursty and is potentially more susceptible to resource contention.
• VM_Lifetime: VM that are long lived may deal with continuous services, which require high-availability.
• Core count and Memory GB: indicators of the size and use of resources of the VM.
The characteristics allow building a detailed profile of the behavior of each VM and the model distinguishes between important and sensitive workloads and less relevant ones that are batch based.
5.2.3. The Hybrid RF-SOM Classification Model.
We have a two stage hybrid model that incorporates unsupervised and supervised learning as our classifier. During the former stage, a Self-Organizing Map (SOM) is trained with the preprocessed VM features. The SOM is an unsupervised clustering method, which maps high-dimensional VM data to a 2D grid. This step clustered VMs according to their similar usage patterns of resources and identified the natural structure and latent cluster of the data. The labels of the clusters in the SOM are then taken as a secondary input feature to the second stage. At the second stage, a Random Forest (RF) classifier is trained. The original set of features with an addition of the SOM-based cluster label is the input to the RF. The RF that is a combination of decision trees learns the non-linear, complex relationship among these features and the target sensitivity classes. Assimilation of SOM and RF allows the model to initially understand the topography of data and subsequently exploit the understanding in enhancing classifications.
5.2.4. Basic Training, Testing, and Performance Appraisal.
The dataset was split into 70D and 30T. The hybrid RF-SOM model was evaluated on the basis of conventional classification measures. The model as demonstrated in Table 3, gave an accuracy of 0.8249, an F1-Score of 0.8241, and a ROC AUC Score of 0.8229. The F1-Score is significant in that it is a harmonic mean of both preciseness and recall because it demonstrates that the model accurately determines both sensitive and insensitive VMs without a high occurrence of false positive and negative occurrences. The large score of the AUC indicates that the model will have a high tendency to rank a randomly selected sensitive VM higher than a randomly selected insensitive one. These findings are the affirmation of the applicability of the hybrid technique to the VM sensitivity classification task.
5.3. Phase 2: Dynamic Control Phase 2: Reinforcement Learning.
5.3.1. State Space Design
At time t, the state s t of the Q-learning agent is a full description of the resource utilization of the whole data center. It is formalized as a set of vectors of the active Physical Machines:
s t = { {CPU_1, RAM 1, NET 1, STIO 1), (CPU 2, RAM 2, NET 2, STIO 2),... (CPU m, RAM m, NET m, STIO m) }
In this case, CPUi, RAMi, NETi, STIOi is 0 to 1 which is the normalized usage of that particular resource on PM i. This is designed to provide the agent with the full picture of the load distribution of the system, which is essential to informed consolidation decisions.
5.3.2.
The action space (A) is discrete in order to simplify the problem further, such that a single action a i denotes a high-level command to a given PM i. The possible commands are:
• a i = -1: Mark the host as underutilized and initiate the process of migrating all its VMs to put it in a sleep state.
• a i = 0: no action on this host, or it is off.
• a i = 1: Designate host as the potential receiver of VMs (keep alive).
This abstract space of action greatly reduces the complexity of a space that defines individual VM migrations, and the Q-learning problem is therefore tractable.
